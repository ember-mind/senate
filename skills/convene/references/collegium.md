# Collegium — Design and Diagnosis

Use for something new to design or something broken to diagnose.

## Runtime budget

- One `magister` call.
- Brief: at most 300 words plus concrete file pointers.
- Plan: at most 500 words.
- Diagnosis: at most 350 words.
- Default model: `sonnet`.
- Override invocation with `model: opus` only when work crosses at least three subsystems or carries security, data-loss, regulatory, or hard-to-reverse architectural risk.

## Stagecraft

> 📐 The Collegium is summoned — <name> takes the floor.

If plan contains genuine choice:

> 🏛️ The plan is carried to the floor — the Senate will tear at it.

## Choose one master

Load `collegium.yaml` beside `SKILL.md`.

- **Vitruvius** — new architecture, system, product, interface, or build sequence.
- **Archimedes** — mechanism, algorithm, performance, feasibility, or cost.
- **Galen** — regression, failure, symptom, differential diagnosis, or minimal cure.

Create one off-craft row only when none fits. Keep shape `{name, craft, method}`. Do not summon multiple masters to appear thorough.

## Procedure

1. Distill brief once. Include objective, constraints, concrete pointers, evidence, definition of done, and unknowns.
2. Select one master row.
3. Launch one `magister` with row verbatim plus brief. Use name `<master-lowercase>-<slug>`.
4. Require PLAN for new work or DIAGNOSIS for broken work.
5. Separate verified evidence from assumptions.
6. Never edit or run implementation.
7. If returned plan contains multiple viable roads, major spend, hard-to-reverse choice, or real user risk, return to Consul and run Senate using plan as brief.
8. Otherwise present plan or diagnosis directly with one next step.

Implementation remains separate. Stop after delivering actual plan. User approval must refer to that plan before Legions march.
